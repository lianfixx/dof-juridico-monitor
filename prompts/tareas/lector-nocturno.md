PREPARACIÓN (en toda tarea)
1. Adjunta el repositorio lianfixx/dof-juridico-monitor con add_repo (acceso de lectura), clónalo con `git clone --depth 1` y lee completos SKILL.md, references/box.md, references/api.md, references/sjf-y-distribucion.md, references/desbloqueo.md y docs/QUALITY_GATE.md. La skill prevalece sobre este mensaje.
2. El box de Simular «main» se maneja con las herramientas mcp__box__shell, mcp__box__read_file y mcp__box__write_file (cárgalas con ToolSearch si están diferidas). Si el conector box no está disponible o no responde tras dos intentos, aplica los planes B y C de references/box.md (TinyFish y, si el chat está vinculado, la Mac) y anota en la bitácora qué vía usaste.
3. En el box, ejecuta `cd /workspace/dof && bash bin/arranque.sh`. Si /workspace/dof/bin no existe o le falta un script (el arranque lo dice), vuelve a escribirlo con mcp__box__write_file desde scripts/box/ del repositorio clonado (mismo contenido, mismo nombre) antes de continuar. Si un script del box difiere del repositorio (compara `sha256sum`), el del repositorio manda.
4. Cada llamada a mcp__box__shell tiene un tope de 600 s y, si se rebasa, la sesión del box se reinicia. Por eso las fuentes se bajan en segundo plano: `bash bin/lanzar.sh <modo>` regresa de inmediato y `bash bin/estado.sh <entrega>` informa el avance (código 3 = sigue en curso). Consulta el estado con llamadas cortas cada 2 o 3 minutos y nunca esperes más de 5 minutos dentro de una sola llamada.
5. Los lectores (subagentes) leen directamente del box con mcp__box__read_file por rangos exactos de página, usando <archivo>.paginas.json (linea_ini, linea_fin). En cada página que esté en `paginas_ocr` del inventario (páginas sin texto o con una imagen grande: formatos, tablas o firmas escaneadas), el lector lee además el OCR de esa página en <archivo>.ocr.txt, y la vista de la imagen cuando el OCR dude. Las ediciones con `ya_reportada: true` no se leen ni se reportan: solo prueban la continuidad de números con el cierre anterior. Reparte bloques sin huecos ni solapamientos; cada lector devuelve páginas leídas, última línea citada, notas por publicación (sujetos, plazos, vigencia, transitorios, efectos, relevancia fiscal/PLD/administrativa/amparo) y estado (INTEGRO, PARCIAL). Las notas se guardan en el box con mcp__box__write_file en /workspace/dof/fuentes/<entrega>/notas/<bloque>.md para que la siguiente tarea las encuentre.
6. Escribe cada script largo de Python o Node en un archivo con la herramienta Write y ejecútalo; no metas scripts largos en comandos encadenados. Si una herramienta pide permiso, no esperes: anota el bloqueo y sigue con lo que sí puedas.
7. Registra la hora real de cada consulta a los portales. Si una vía falla, agota A, B y C antes de declarar PARCIAL.

TAREA DE HOY: LECTOR NOCTURNO (sin correo)
A. En el box: `cd /workspace/dof && bash bin/lanzar.sh noche` y sigue el avance con `bash bin/estado.sh <mañana>` hasta OK o CON_FALLOS. La entrega es la de mañana (fuentes/<mañana>/). Lunes: baja desde el corte del jueves (sus vespertinas o extraordinarias tardías) hasta hoy lunes, y el Semanario del viernes. Miércoles: baja desde el corte del martes (sus tardías) y el miércoles. Lo ya reportado en el cierre anterior queda marcado `ya_reportada` y no se lee.
B. Verifica `compuerta_fuentes` de fuentes/<mañana>/manifiesto.json: páginas reales = declaradas, números consecutivos desde la última edición ya reportada, anexos aparte localizados, OCR terminado (sin `ocr_pendiente`). Si falta algo, vuelve a lanzar (es reanudable) o repite el paso que falló con la vía B o C.
B2. Relevo con el lector por API (references/api.md, «Relevo con la suscripción»). Lo que el lector por API ya dejó íntegro no se vuelve a leer desde cero; lo que no, lo lees tú como siempre.
   1. Para el repositorio privado, clona lianfixx/dof-trabajo con `git clone --depth 1 https://github.com/lianfixx/dof-trabajo` (esta tarea lo tiene entre sus repositorios; en las ejecuciones programadas add_repo no existe y el acceso viene de los repositorios de la tarea).    2. En el box: `python3 bin/relevo_lista.py <mañana>`. Guarda esa línea JSON, tal cual, en un archivo de esta sesión (lista.json) con la herramienta Write.
   3. En esta sesión: `python3 scripts/api/relevo.py comprobar <clon de dof-trabajo>/fuentes/<mañana>/ESTADO_API.json lista.json`. Devuelve TOTAL, PARCIAL o NINGUNO y, documento por documento, `por_api` o `por_suscripcion` con su motivo. La decisión es de ese programa, no tuya: no la cambies.
   4. Consulta la corrida cada 3 a 5 minutos con llamadas cortas (`gh api "repos/lianfixx/dof-trabajo/actions/workflows/lector-api.yml/runs?per_page=1"`), 50 minutos como máximo; al terminar, `git pull` y repite el paso 3. Si no puedes lanzarlo o consultarlo, no esperes. Lo que al final siga `por_suscripcion` lo lees tú.
   5. Muestra de control de lo que quedó `por_api`: toma de `fuentes/<mañana>/notas/PRELIMINAR_API.md` las dos primeras candidatas del documento con más páginas, lee tú esas publicaciones en el box y compáralas con su nota (título, páginas, vigencia, plazos y una cita literal). Si un dato de la nota es falso o la publicación no está donde dice, el relevo se anula: trata todos los documentos como `por_suscripcion` y anota por qué.

Escribe en el box, con mcp__box__write_file, /workspace/dof/fuentes/<mañana>/notas/RELEVO_API.json: el veredicto completo de relevo.py y además `muestra_de_control` (qué revisaste y el resultado), `anulado` (true o false) y `hora_local`.
